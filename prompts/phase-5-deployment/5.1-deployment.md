# Phase 5 Implementation Prompt: Production Deployment

## Goal
Prepare, configure, and document deployment for Vibelearn so that the React (Vite) frontend deploys cleanly to Vercel and the Node.js (Express) backend deploys cleanly to Render with complete production environment variables, SPA routing rewrites, and CORS security.

---

## Skills Read
- `docs/system_design/frontend.md` — Vite React frontend architecture, client environment variables
- `docs/system_design/backend.md` — Node.js Express backend architecture, Render deployment requirements
- `docs/AGENTS.md` — boundary rules, secret key protection, deployment verification checklist

---

## Code Inspected

### Frontend
- `frontend/package.json` — build script (`vite build`), output directory (`dist`)
- `frontend/vite.config.js` — Vite configuration
- `frontend/.env.example` — `VITE_CLERK_PUBLISHABLE_KEY`, `VITE_API_URL`

### Backend
- `backend/package.json` — start script (`node src/index.js`), main entry (`src/index.js`)
- `backend/src/config/index.js` — port, nodeEnv, databaseUrl, clerkPublishableKey, clerkSecretKey, frontendUrl
- `backend/src/index.js` — CORS configuration and Express listener
- `backend/.env.example` — environment variables template

---

## Decisions & Assumptions

### 5.1 — Workspace Quality & Linting
- Ensure `npm run lint` and `npm run build` pass cleanly in both `frontend` and `backend` with zero errors.

### 5.2 — Frontend Vercel Configuration
- Create `frontend/vercel.json` with SPA route rewrites:
  ```json
  {
    "rewrites": [
      { "source": "/(.*)", "destination": "/index.html" }
    ]
  }
  ```
- Ensure client-side deep links (e.g., `/courses/:slug`, `/my-learning`) resolve properly without 404 on refresh.

### 5.3 — Backend Render Configuration
- Create `backend/render.yaml` (and root `render.yaml`) declaring the Web Service blueprint with Node runtime, build command (`npm install`), and start command (`npm start`).
- Enhance CORS in `backend/src/index.js` to handle both single frontend origin and comma-separated multiple origins (e.g. Vercel production + preview deployments).

### 5.4 & 5.5 — Environment Variables & Live Verification Documentation
- Create a clear deployment guide (`docs/DEPLOYMENT.md`) specifying step-by-step setup, required production environment variables for both platforms, and verification checklists.

## Security Considerations
- `CLERK_SECRET_KEY` and `DATABASE_URL` are strictly server-side on Render and never exposed in Vercel client bundles.
- `VITE_CLERK_PUBLISHABLE_KEY` and `VITE_API_URL` are the only variables exposed on Vercel.
- CORS restricted to the verified `FRONTEND_URL` production origins.

---

## Acceptance Criteria
- [ ] `frontend/vercel.json` exists and correctly redirects all route paths to `/index.html`.
- [ ] `backend/render.yaml` defines service specs, start command, and environment variable slots.
- [ ] Backend CORS correctly parses production frontend URLs.
- [ ] `npm run lint` passes across both frontend and backend.
- [ ] `npm run build` succeeds in frontend.
- [ ] `docs/DEPLOYMENT.md` documents exact deployment steps and required env variables.
