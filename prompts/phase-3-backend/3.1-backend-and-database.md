# Implementation Prompt: Phase 3 - Backend & Database

## 1. Goal
Implement the complete backend architecture for **Vibelearn** using Node.js, Express, Drizzle ORM, and Supabase PostgreSQL. This phase defines the database schema (`users`, `courses`, `modules`, `lessons`, `progress`), generates database migrations, builds the data seeding script parsing `docs/seed.ndjson` and `docs/videos.json`, and exposes read-only public endpoints as well as protected progress endpoints adhering to the strict layered architecture (`Routes -> Controllers -> Services -> Repositories`).

## 4. Decisions & Assumptions
- **Database Driver**: Use `postgres` (postgres.js) with `drizzle-orm/postgres-js` for lightweight, modern, and performant connection to Supabase PostgreSQL without native binary compilation dependencies.
- **Connection Resilience**: In `src/db/index.js`, instantiate the Drizzle client with connection error handling. If `DATABASE_URL` is empty or placeholder (e.g., during offline verification or initial repo setup), provide clear diagnostics and graceful handling rather than an unhandled process crash.
- **Schema Mapping**:
  - `users`: `id` (varchar PK, Clerk User ID), `email` (varchar), `createdAt` (timestamp).
  - `courses`: `id` (uuid PK defaultRandom), `title` (varchar not null), `slug` (varchar not null unique), `summary` (text), `coverImageUrl` (varchar), `createdAt` (timestamp defaultNow).
  - `modules`: `id` (uuid PK defaultRandom), `courseId` (uuid not null references courses.id), `title` (varchar not null), `position` (integer not null).
  - `lessons`: `id` (uuid PK defaultRandom), `moduleId` (uuid not null references modules.id), `title` (varchar not null), `slug` (varchar not null unique), `youtubeVideoId` (varchar), `notes` (text), `position` (integer not null).
  - `progress`: `id` (uuid PK defaultRandom), `userId` (varchar not null references users.id), `lessonId` (uuid not null references lessons.id), `isCompleted` (boolean default false), `resumeTimestamp` (integer default 0), `updatedAt` (timestamp defaultNow).
  - Drizzle Relations for declarative joins (`courses.modules`, `modules.lessons`, `lessons.module`, `progress.lesson`, `progress.user`).
- **Seeding Pipeline (`src/db/seed.js`)**:
  - Parse `docs/seed.ndjson` line by line.
  - Parse `docs/videos.json` for YouTube video mappings (`id` field).
  - Extract courses, parse nested modules, link lessons, extract notes as formatted markdown text, and compute positional indexes.
  - Insert records idempotently into the database.
- **Layered Architecture (`Routes -> Controllers -> Services -> Repositories`)**:
  - Repositories handle pure SQL / Drizzle queries.
  - Services handle business logic and formatting.
  - Controllers orchestrate req/res, params validation, and error passing to `next()`.
  - Routes map REST endpoints:
    - `GET /api/courses`: Returns all courses with modules count and summary.
    - `GET /api/courses/:slug`: Returns course by slug with nested modules and lessons.
    - `GET /api/lessons/:slug`: Returns lesson content, YouTube video ID, and notes.
    - `GET /api/progress`: Protected endpoint returning all progress for the authenticated user.
    - `POST /api/progress`: Protected endpoint upserting lesson progress (`lessonId`, `isCompleted`, `resumeTimestamp`).
- **Auth Middleware**:
  - `src/middlewares/auth.middleware.js`: Validates Clerk JWT or authenticated user header. When running in local development with placeholder keys, supports mock user header (`x-user-id` or demo user) for testability.

## 7. Security Considerations
- Database credentials remain strictly on the backend (`DATABASE_URL` in `.env`).
- No database credentials or Clerk secret keys are exposed to the client.
- Progress writes and reads require an authenticated user ID.
- Centralized error handler masks internal database connection details in production responses.
